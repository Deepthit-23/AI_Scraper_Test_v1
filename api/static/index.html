Coverage & Limitations

What the pipeline handles well, where it falls short, and what to validate before production use.

Product catalog coverage
Works best on branded, discrete products with a manufacturer website or major retailer listing. Commodity and unbranded items typically skip web enrichment — no reliable source to search.
Web enrichment source quality
Sources are ranked: manufacturer pages → distributors → retailers. MPN Verified (teal badge) means the exact MPN appeared on the source page. Amber "not confirmed" rows extracted specs from a related product on the same brand — treat those attributes as approximate and worth spot-checking.
JavaScript-rendered pages
Some manufacturer sites require a headless browser. The pipeline scrapes with ScraperAPI, which handles most sites but not all JS-heavy SPAs. Failed scrapes fall back to no enrichment for that row rather than erroring the whole run.
LLM extraction accuracy
Attributes are extracted by openai/gpt-oss-120b via Groq. The model is instructed to quote verbatim source snippets and avoid inference — but low-confidence attributes should be spot-checked, especially numeric values and model numbers. The pipeline applies an adaptive token budget (≤5,500 source tokens) to stay under the 8,000 TPM limit.
Groq free-tier rate limits
The free Groq tier allows ~100,000 tokens/day. A 30-row enrichment run uses roughly 35,000–50,000 tokens when there are no cache hits. Previous extractions are cached by source URL — re-running the same rows costs zero tokens. A full 200-row run may approach the daily limit; the quota resets at midnight UTC.
Category classification
Classification uses rule-based matching first, falling back to the LLM. Rows that match no rule are classified as "Hardware > General Hardware > Miscellaneous" — a safe fallback, but it indicates the taxonomy doesn't cover that product type yet.
Description templates
All five description fields (Mobile, Invoice, Short, Long, Retail) are generated from templates using extracted attributes — no additional LLM call. Character limits are enforced: Invoice ≤ 40 chars, Mobile ≤ 25 chars. The _invoice_desc_ok and _mobile_desc_ok columns in the output CSV flag compliance.
